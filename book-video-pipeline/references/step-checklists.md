# 每步流程自检清单

> **用法**：每完成一个流程节点（标 `needs_review` 之前），必须拿出对应步骤的检查项逐条核对。
> 发现 ✗ 直接修复，修完重查，全绿才提交审核。**正确的项不修改**（避免过度改动）。
> 检查结果记入该步 manifest note（如 `--note "Q6自检：9项全绿，修复了黑屏(cloud-bg延长)"`）。
>
> 本文件收录**真实踩过的坑**，每条标注「坑源」。新增坑随时追加。

## 自检铁律

1. **完成即查**：每完成一个节点，立即对照本文件对应步骤的检查项
2. **有问题就修**：发现 ✗ 直接修复，不累积到后面
3. **修完再查**：修复后重新核对受影响的项，确认转 ✓
4. **正确不动**：已 ✓ 的项不反复改动，避免引入新问题
5. **记录过程**：在 manifest note 记录「查了几项/修了什么」，便于追溯

## A 线·金句流（Q1-Q8）

### Q1 — 选书 + 获取金句数据

- **Q1-1 书封库存在**：`assets/book-covers/{书名}.png` 存在；不存在则 🔴 blocked，提示补齐
  - 坑源：ep007 首次未检查书封，到 Q6 才发现缺
- **Q1-2 bookId 锁定**：同书多版本（如「影响力」vs「影响力珍藏版」）必须用正确 bookId，记录到 manifest
  - 坑源：ep007 珍藏版 bookId=823434，非普通版
- **Q1-3 章节精准（同书多集）**：续集聚焦某章时，用 `chapterUid` 参数获取该章专属划线，不用全书 Top20 混排
  - 坑源：ep008 第一章 Top10 用 chapterUid=16 精准获取，而非全书排行
- **Q1-4 与前集去重**：同书系列时，核查前集已用金句，避免重复

### Q2 — 金句筛选 + 拼接

- **Q2-1 字数红线**：总字数（含引入句）落在 **120-175 字** 区间；超限时优先删句或截半句，不放宽红线
  - 坑源：ep008 初选 5 句 287 字超红线 112 字
- **Q2-2 单句长度**：每句 **≤35 字**；书中 60+ 字的论述段落必须截取核心半句（不损原意）
  - 坑源：ep008 rank-6/7 各 60+ 字，需截取
- **Q2-3 情绪递进**：排序有逻辑——日常入口 → 机制揭示 → 深层原理 → 总收束，非随机拼凑
- **Q2-4 朗读时长估算**：字数 ÷ 语速（1.0x 约 4-4.5 字/秒）≤ 60 秒

### Q3 — 配音

- **Q3-1 倍速参数**：`--speed` 值与当前默认一致（**1.0x**）；用户指定其他倍速时以用户为准
  - 坑源：ep008 用户要求 1.0x（原默认 0.9x），同时更新了插件默认值
- **Q3-2 试听样本真实**：用**本集前 40-60 字**生成样本，不用库内旧样本冒充
- **Q3-3 时长记录**：完整配音生成后，记录实际秒数到 manifest（用于后续时间轴）

### Q4 — 实拍素材

- **Q4-1 方向正确**：自然风光、山水、森林、湖泊、日出、云雾；**不选**城市街景、人群、室内静物
- **Q4-2 分辨率**：720p-1080p（竖边高度 720-1080px）
- **Q4-3 单文件体积**：≤10MB；超限脚本自动换 `_medium`/`_small` 变体
- **Q4-4 素材充裕度**：每组素材总时长 ≥ 该段配音时长 ×1.5（留选择空间）
- **Q4-5 数量**：每组 2-3 个 clip，总数 ≥ 金句数 ×2

### Q5 — 封面（素材截图 + 手写体）

- **Q5-1 来源正确**：从**素材视频**（非成片）抽 6 张候选图——封面在 Q6 合成前制作时，必须用原始素材
  - 坑源：ep008 首版错误地从成片抽帧
- **Q5-2 6 宫格预览**：6 张候选拼成 3×2 网格，让用户一次性选定
- **Q5-3 品牌卡 logo**：左上角有 `corner-lockup.png`（距左/上 40px，320×80px，opacity 0.85）
  - 坑源：ep008 cover-shier.py 首版完全没有 logo 合成逻辑，封面缺品牌卡
- **Q5-4 字体**：LXGW 霞鹜文楷 Regular，白色，无底条无描边
- **Q5-5 双尺寸**：`cover-final.png`（3:4，1080×1440）+ `cover-final-9x16.png`（9:16，1080×1920）
- **Q5-6 低饱和处理**：背景已做 Color 0.85 + Brightness 1.05 治愈感处理

### Q6 — hyperframes 合成

- **Q6-1 无黑屏（最重要）**：所有时段有背景元素覆盖；重点检查**转场衔接处**——`cloud-bg` 结束时间 ≥ 首个金句素材开始时间，无空窗
  - 坑源：ep008 首版 cloud-bg 2.0-4.0s，clip-q1 从 6.0s 才开始，4.0-6.0s 黑屏 2 秒
- **Q6-2 书封快闪 10 本**：从书封库随机选 10 本，**排除本集书**（本集书用于落定段）
- **Q6-3 字幕无重叠**：相邻字幕间留 **≥0.1s 间隙**；字幕 duration 不覆盖下一句的 start
  - 坑源：ep008 首版字幕 duration 算成「金句时长+0.3」，尾巴与下一句头部重叠
- **Q6-4 字幕领先旁白**：字幕 start = 对应金句旁白 start - **0.3s**
- **Q6-5 品牌角标全程常驻**：`#brand-logo` 的 data-start=0、data-duration=总时长
- **Q6-6 BGM 音量**：`data-volume="0.15"`，淡入 1s 淡出 2s，不盖人声
- **Q6-7 intro/outro 静音**：`muted playsinline`，不带原片背景音
- **Q6-8 lint + check 0 error**：`npx hyperframes lint` 和 `npx hyperframes check` 均 0 error（warning 视情况）
- **Q6-9 抽帧验证**：从成片抽关键时段帧（书封落定 t≈3s、各金句段中段、转场衔接处），**逐张确认非黑帧**（文件大小 >100KB 通常为正常画面，<50KB 疑似黑帧）
  - 坑源：ep008 黑屏问题就是通过抽帧发现 t=4.5s 文件仅 29KB
- **Q6-10 总时长**：≤60s（intro + 正文 + outro）

### Q7 — 字幕校准

- **Q7-1 每条字幕 ≥3s**（最短停留时长，保证可读）
- **Q7-2 SRT 导出**：`04-video/subtitle.srt` 已生成，时间码与 index.html 的 data 属性一致
- **Q7-3 断行可读**：每条字幕 2-3 行，每行 ≤12 字，无超长无断点行

### Q8 — 发布准备

- **Q8-1 标题**：≤20 字，含书名
- **Q8-2 标签**：含三大固定（`#读书 #好书推荐 #情感共鸣`）+ 书名/主题相关标签
- **Q8-3 合规检查**：无医疗/投资/绝对化承诺，无导流私域，无虚假稀缺
- **Q8-4 封面图就位**：双尺寸封面已生成且通过审核

## 报告格式

每次自检后，在 manifest note 记录摘要（逐项不必写，记关键）：

```
Q6自检：10项查，9绿1修（修复黑屏：cloud-bg duration 2.0→4.0）
Q5自检：6项全绿
Q1自检：4项全绿，与前集ep007去重确认
```

**不要跳过自检直接提交审核。制作者有确认偏差，自检是第一道防线。**
